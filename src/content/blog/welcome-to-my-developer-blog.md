이 블로그는 현직 개발자가 실제로 개발하고, 공부하고, 실패하고, 해결한 과정을 기록하는 공간입니다.

## 왜 기록하는가

같은 문제를 두 번 검색하지 않기 위해서입니다.

개발을 하다 보면 한 번 해결한 문제를 몇 달 뒤에 다시 만나는 일이 반복됩니다. 그때마다 처음부터 다시 검색하는 대신, 당시의 에러 메시지와 해결 명령어를 그대로 남겨 두면 다음에는 몇 분이면 끝납니다. 그 기록이 같은 문제를 겪는 다른 사람에게도 도움이 된다면 더 좋습니다.

## 어떤 내용을 다루는가

특정 기술 하나에 집중하기보다 실제로 손대고 있는 범위를 넓게 다룹니다.

- Software Development, Linux / Ubuntu, Docker
- AI / Machine Learning, LLM / Local AI, Computer Vision, OCR
- GPU / CUDA
- CAD, Engineering, Wireless / SDR
- Certification
- Personal Projects

## 어떤 방식으로 쓰는가

글의 기본 흐름은 항상 같습니다.

> 개발 → 문제 발생 → 해결 → 기록

일반적인 설명보다 다음을 우선합니다.

1. 실제 에러 메시지
2. 실제로 실행한 명령어와 코드
3. 실험 결과와 실패 과정
4. 최종 해결 방법과 개인적인 판단

## 블로그 구성
